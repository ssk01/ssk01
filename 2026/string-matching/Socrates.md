# 本次讨论的落实

- 教程主线：从 HN 评论的 YouTube 筛选需求开始，沿一条真实评论解释候选过滤、定位和验证。
- 实例：同一条评论中 `easy` 的 y 验证失败，链接中 `youtube` 的 y 验证成功，并跨越 16 字节块边界。
- 数据：固定 16 MiB 以内的完整真实评论行，保存校验值与来源。
- 实验：两种十桶分布各抽三个词，加四个机制对照，去重后共 64 个 key 跑三种形状、两种核心实现，另保留 libc 对照；统计口径、图表与分析统一写入 README。
- 指令：区分 intrinsic 与生成汇编，提供独立编译入口核对过滤、mask 提取、候选定位和清除。

完整讲解统一维护在 [README.md](README.md)，本文件只保留讨论决策。

频率分析分开处理首字节密度、完整模式命中、首字节频率。新增标量起点与字节比较统计，用实际工作量解释三种形状；分桶图展示相对加速，机制图区分相对优势与绝对耗时。实现讲解补全逐字节比较与 libc 单字节搜索加验证路径。

机制图以“首字节过滤效率与候选验证成本”为主题，分别说明两张散点图的坐标、单位、颜色和实测例子；频率章节按指标解释收益。

补充分组实验：六组固定词长与完整词频区间，三组固定首字符与词长；选词规则独立于性能结果，保存逐轮计时与命中、扫描、候选计数，教程同时展示散点和组内对照表。

教程按“结论—图—读图说明”组织；删去重复解读，完整抽样明细保留在 CSV，正文保留逐词图、关键对照和实现伪代码。生成脚本同步维护文案。

运行时跟踪确认：基准调用进入系统 `_platform_memchr`，使用 16 字节 NEON 减法与归约。教程区分系统搜索每次返回一个候选，与手写 SIMD 保留整块 mask 的处理方式；检查脚本与证据随项目保存。
