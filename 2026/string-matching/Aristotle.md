# 用户问题与实验目标

本项目从 Karpathy 的 HackerTube 场景出发：在 Hacker News 评论正文中查找 YouTube 视频相关内容。

用户关心的实现问题：

- SIMD 的字节相等比较怎样同时筛选多个起点？
- 找到第一个候选位置后，如何验证、继续寻找或返回？
- 前缀、后缀、包含要用同一组 key 比较，提供手写标量与 SIMD 六个 case。
- 比较默认自动向量化；讲清实际用到的指令和吞吐口径。

对教程的具体要求：

- 以真实 HN / YouTube 场景组织叙述，使用真实评论讲解。
- 性能输入只取一部分真实数据，不使用合成语料。
- 先统计词频、首字节频率与首字节分布，再设计 YouTube 之外的 key，画图解释性能差异。
- playground 中的 README 是唯一完整教程；代码、样本元数据与实测结果一起维护。

新增要求：

- 展开 `scalar_equal` 的实际实现与 `memchr` 的工作方式。
- 首字节频率和全文词频各分十桶，按规则从桶内选词。
- 解释 contains 与 prefix/suffix 的 SIMD 收益为何不同。
- 把机制图的坐标、点与频率含义讲明白，分别回答“绝对变快”和“相对优势变大”。

- 教程面向未参与讨论的读者，标题与图解应独立交代对象和指标，避免沿用对话中的指代。

- 扩大真实词集合，测量后按相近完整词频和词长分组，比较首字符频率；同时用相同首字符的组观察完整词频影响。

- 复查并简化教程与图片；每张图之前先给一句能概括实测结果的结论。

- 检查当前机器实际调用的 memchr 是否使用 SIMD，并把运行时证据和手写 SIMD 的差别写入教程。

- 提交时不包含原始样本文件；保留来源、校验值和演示评论。
