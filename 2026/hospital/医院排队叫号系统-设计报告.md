# 医院排队叫号系统 — 系统设计报告

> **30 分钟 System Design 展示**
> 规模：单院区日均 5000+ 号源，50+ 科室，200+ 诊室

---

## 1. 需求澄清（2 min）

### 功能需求
| 模块 | 描述 |
|------|------|
| 患者签到 | 自助机/扫码取号，生成排队号码，分配优先级 |
| 队列管理 | 按科室 + 优先级排队，支持过号重排、插队 |
| 医生叫号 | 医生端点击"下一位"，系统自动弹出最高优先级患者 |
| 大屏展示 | 候诊区大屏实时显示各科室当前叫号、等待列表 |
| 语音播报 | 叫号时 TTS 播报"请XXX号到X诊室" |
| 复诊/回诊 | 做完检查回来的患者优先插入队列 |

### 非功能需求
- **低延迟**：叫号到屏幕刷新 < 500ms
- **高可用**：门诊时段不可宕机，99.9% uptime
- **公平性**：同优先级 FIFO，插队有审计日志
- **扩展性**：支持多院区部署

### 核心复杂度
> **多维度优先级队列**：紧急程度 × 是否回诊 × 预约时段 × 到达时间 → 需要一个可配置的排序策略

**关键设计决策：**
- **Redis Sorted Set 做队列**：score = priority * 10¹⁵ + timestamp_ns，天然支持优先级 + FIFO
- **WebSocket 做推送**：大屏无需轮询，延迟 < 100ms
- **PostgreSQL 做持久化**：审计、报表、数据恢复

## 3. 数据模型（3 min）

### 3.1 核心实体

```
Patient (患者)
├── patient_id      UUID
├── name            string
├── id_card         string
├── phone           string

Ticket (号源 — 一次排队)
├── ticket_id       UUID
├── patient_id      FK → Patient
├── department_id   FK → Department
├── queue_number    string      // "A035" 展示用
├── priority        int         // 0=急诊 1=回诊 2=老年 3=普通 4=预约迟到
├── check_in_time   timestamp   // 签到时间，作为 FIFO 依据
├── status          enum        // WAITING | CALLED | SERVING | DONE | NOSHOW
├── doctor_id       FK → Doctor (nullable, 分配后填充)

Doctor (医生)
├── doctor_id       UUID
├── name            string
├── department_id   FK → Department
├── room_no         string      // "302"
├── status          enum        // OFFLINE | IDLE | BUSY

Department (科室)
├── department_id   UUID
├── name            string      // "心血管内科"
├── prefix          string      // "A" 叫号前缀
├── current_number  int         // 当前已叫到第几号
```

### 3.2 Redis 数据结构

```
# 科室排队队列 (Sorted Set)
Key:   queue:dept:{dept_id}
Score: priority * 10^15 + check_in_time_ns
Value: ticket_id

# 医生当前状态 (Hash)
Key:   doctor:{doctor_id}
Field: status, current_ticket_id, room_no

# 诊室-医生映射 (Hash)
Key:   room:{room_no}
Field: doctor_id, status

# 叫号大屏频道 (Pub/Sub)
Channel: display:{dept_id}
Message: { type: "CALL", ticket_id, queue_number, room_no, patient_name }
```

## 5. 核心算法（5 min）

### 5.1 优先级计算策略

```
函数 CalcPriority(patient, is_return, is_elderly):
    基础优先级表:
        急诊     → 0   (红色通道)
        回诊患者  → 1   (检查回来，优先插队)
        80岁以上  → 2   (老年优待)
        预约时段内 → 3   (正常预约)
        预约迟到   → 4   (迟到降权)
        现场挂号   → 5   (最低)

    输出: 优先级 int
```

### 5.2 入队算法

```
函数 Enqueue(dept_id, patient_id, priority):
    ticket_id    = UUID()
    queue_number = GenerateQueueNumber(dept_id)   // "A035"
    score        = priority * 10^15 + now_ns()
    
    Redis: ZADD queue:dept:{dept_id}  score  ticket_id
    Redis: HSET ticket:{ticket_id}
           patient_id, queue_number, priority, status="WAITING", check_in_time
    
    PG:   INSERT INTO tickets(...)
    
    广播: PUBLISH display:{dept_id} { type:"QUEUE_UPDATE", ... }
    
    返回: ticket_id, queue_number, 预估等待(队列长度 * 平均就诊时间)
```

### 5.3 叫号出队算法

```
函数 CallNext(doctor_id):
    doctor     = GetDoctor(doctor_id)
    dept_id    = doctor.department_id
    
    // 原子操作：弹出最高优先级最早到达的 ticket
    result     = Redis Lua Script: PopNextFromQueue(dept_id)
    
    如果 result 为空:
        返回 { "message": "当前无人等待" }
    
    ticket_id  = result
    
    更新状态:
        Redis: HSET ticket:{ticket_id} status="CALLED" doctor_id
        Redis: HSET doctor:{doctor_id} status="BUSY" current_ticket_id
    
    广播大屏:
        PUBLISH display:{dept_id} {
            type: "CALL",
            ticket_id, queue_number, patient_name, room_no
        }
    
    触发语音播报(异步):
        PUSH TTS任务到消息队列
    
    返回: { ticket_id, queue_number, patient_name, room_no }
```

## 6. 核心伪代码（5 min）

### 6.1 队列引擎 — Redis Lua 原子出队

```lua
-- PopNextFromQueue.lua (在 Redis 服务端原子执行)
-- KEYS[1] = queue:dept:{dept_id}
-- 返回: ticket_id 或 nil

local tickets = redis.call('ZRANGE', KEYS[1], 0, 0)
if #tickets == 0 then
    return nil
end

local ticket_id = tickets[1]

-- 检查是否已叫号超时 (过号 3 分钟自动跳过)
local ticket_key = 'ticket:' .. ticket_id
local status = redis.call('HGET', ticket_key, 'status')
if status == 'CALLED' then
    local called_time = redis.call('HGET', ticket_key, 'called_time')
    if called_time and (os.time() - called_time) > 180 then
        redis.call('HSET', ticket_key, 'status', 'NOSHOW')
    end
end

redis.call('ZREM', KEYS[1], ticket_id)
return ticket_id
```

### 6.2 签到服务伪代码

```
服务 CheckInService:

    方法 签到(患者ID, 科室ID, 是否回诊):
        如果 是否回诊:
            优先级 = PRIORITY_RETURN
        
        否则:
            科室 = 查询科室(科室ID)
            是否急诊 = 判断急诊(患者ID)
            是否老年 = 判断年龄(患者ID, 80)
            
            如果 是否急诊:
                优先级 = PRIORITY_EMERGENCY
            否则如果 是否老年:
                优先级 = PRIORITY_ELDERLY
            否则:
                优先级 = PRIORITY_NORMAL
        
        ticket_id = UUID()
        queue_number = 生成叫号码(科室.prefix, 科室.current_number + 1)
        
        锁 = 获取分布式锁("dept:" + 科室ID)
        科室.current_number += 1
        更新科室号源计数()
        释放锁
        
        score = 优先级 * 10^15 + 当前时间纳秒()
        
        Redis事务:
            ZADD "queue:dept:" + 科室ID  score  ticket_id
            HSET "ticket:" + ticket_id
                patient_id    = 患者ID
                queue_number  = queue_number
                priority      = 优先级
                status        = "WAITING"
                check_in_time = 当前时间()
        
        PostgreSQL异步写入:
            INSERT INTO tickets (ticket_id, patient_id, department_id,
                                 queue_number, priority, status, check_in_time)
        
        广播队列更新("display:" + 科室ID)
        
        返回 {
            ticket_id:    ticket_id,
            queue_number: queue_number,
            estimated_wait: 预估等待时间(科室ID, 优先级),
            position:     获取队列位置(科室ID, ticket_id)
        }
```

### 6.3 叫号服务伪代码

```
服务 CallService:

    方法 叫下一位(医生ID):
        医生   = 查询医生(医生ID)
        科室ID = 医生.科室ID
        
        如果 医生.当前挂号ID 不为空:
            抛出错误 "请先完成当前就诊"
        
        锁 = 获取分布式锁("call:" + 科室ID)
        
        ticket_id = Redis执行Lua(PopNextFromQueue, "queue:dept:" + 科室ID)
        
        如果 ticket_id 为空:
            释放锁
            返回 { message: "当前无人等待" }
        
        挂号信息 = Redis获取("ticket:" + ticket_id)
        患者     = 查询患者(挂号信息.patient_id)
        
        现在 = 当前时间()
        Redis事务:
            HSET "ticket:" + ticket_id
                status       = "CALLED"
                doctor_id    = 医生ID
                called_time  = 现在
                room_no      = 医生.诊室号
            
            HSET "doctor:" + 医生ID
                status            = "BUSY"
                current_ticket_id = ticket_id
        
        释放锁
        
        调用方信息 = {
            type:         "CALL",
            ticket_id:    ticket_id,
            queue_number: 挂号信息.queue_number,
            patient_name: 患者.姓名,
            room_no:      医生.诊室号,
            timestamp:    现在
        }
        
        Redis发布("display:" + 科室ID, 调用方信息)
        
        异步发送语音播报(调用方信息)
        
        PostgreSQL异步写入:
            INSERT INTO call_logs (ticket_id, doctor_id, called_time)
        
        返回 {
            ticket_id:    ticket_id,
            queue_number: 挂号信息.queue_number,
            patient_name: 患者.姓名,
            patient_age:  患者.年龄
        }
```

### 6.4 大屏推送服务伪代码

```
服务 DisplayService:

    初始化():
        订阅 Redis频道:
            模式匹配 "display:*"
    
    处理科室消息(科室ID, 消息):
        连接池 = WebSocket连接管理.获取科室连接(科室ID)
        
        对于 每个连接 在 连接池:
            如果 连接.存活():
                连接.发送(JSON(消息))
            否则:
                连接池.移除(连接)
    
    方法 快照(科室ID):
        // HTTP 降级接口，当 WebSocket 不可用时轮询
        队列列表 = Redis ZRANGE("queue:dept:" + 科室ID, 0, 19)
        挂号详情列表 = Redis批量获取("ticket:" + 每个队列列表项)
        
        当前叫号 = Redis获取("dept:" + 科室ID + ":current_call")
        
        返回 {
            calling:      当前叫号,
            waiting_list: 挂号详情列表[0..19],
            total_waiting: Redis ZCARD("queue:dept:" + 科室ID)
        }
```

### 6.5 过号处理伪代码

```
服务 QueueService:

    方法 过号重排(ticket_id):
        挂号信息 = 获取挂号(ticket_id)
        
        如果 挂号信息.状态 不是 "CALLED":
            抛出错误 "只有已叫号未就诊的可以重排"
        
        现在 = 当前时间()
        过号时长 = 现在 - 挂号信息.called_time
        
        如果 过号时长 > 600秒:
            // 超过 10 分钟，排到队尾
            新优先级 = 挂号信息.优先级 + 2
        否则 如果 过号时长 > 180秒:
            // 3-10 分钟，排到同优先级队尾
            新优先级 = 挂号信息.优先级
        否则:
            // 3 分钟内，保持原位
            抛出错误 "叫号不足3分钟，请稍后再来"
        
        新评分 = 新优先级 * 10^15 + 当前时间纳秒()
        
        Redis:
            ZADD "queue:dept:" + 挂号信息.科室ID  新评分  ticket_id
            HSET "ticket:" + ticket_id  status = "WAITING"
        
        广播队列更新(...)
```

## 7. 扩展性 & 边界情况（3 min）

### 7.1 扩展策略

| 场景 | 方案 |
|------|------|
| 多院区 | 院区 ID 前缀分片，`queue:{hospital}:{dept}`，Redis Cluster 按院区分片 |
| 高并发签到 | 号源计数器用 Redis INCR 原子递增，无锁设计 |
| 大屏断连 | WebSocket 心跳 + 自动重连 + HTTP 轮询降级 |
| Redis 故障 | Sentinel 哨兵自动切换，重启后从 PG 恢复队列 |
| 语音播报延迟 | 异步消息队列 (RabbitMQ/Kafka)，TTS 服务独立扩容 |

### 7.2 边界情况处理

```
情况 1: 医生连续点击"下一位"
├── 方案: 分布式锁 "call:{dept_id}"，同一科室同一时间只能有一个叫号操作
└── 超时: 3 秒自动释放，防止死锁

情况 2: 患者签到后离开医院(过号)
├── 方案: 叫号后 3 分钟未到，自动标记 NOSHOW
└── 患者回来: 调用 /api/queue/rejoin 重排队尾

情况 3: 急诊患者插队
├── 方案: priority=0 天然排到最前
└── 审计: 所有插队操作记录 audit_log，包含操作人、原因

情况 4: 医生临时停诊
├── 方案: doctor.status = OFFLINE，已分配号源转给同科室其他医生
└── 通知: 大屏提示"XX医生停诊，请到导诊台重新分配"

情况 5: 下午签到(科室当前号从1开始)
├── 方案: 每日零点定时任务重置 department.current_number = 0
└── 号源格式: "A001" → 前缀 + 3位序号，每日重置
```

### 7.3 监控指标

```
系统监控:
├── queue_length:{dept_id}       # 各科室排队长度 (Gauge)
├── avg_wait_min:{dept_id}       # 平均等待时间 (Gauge)
├── call_latency_ms              # 叫号响应延迟 (Histogram)
├── display_push_latency_ms      # 大屏推送延迟 (Histogram)
├── check_in_qps                 # 签到 QPS (Counter)
└── no_show_rate:{dept_id}       # 过号率 (Gauge)

告警规则:
├── 排队人数 > 50 → 短信通知科室主任
├── 平均等待 > 60min → 通知导诊台增开诊室
└── 叫号延迟 > 2s → P0 告警
```

## 8. 总结 & 选型对照（2 min）

```
┌─────────────────┬──────────────────────┬─────────────────────┐
│    选型          │       方案 A          │      方案 B          │
├─────────────────┼──────────────────────┼─────────────────────┤
│ 队列存储        │ Redis Sorted Set ✅   │ PostgreSQL SKIP LOCKED│
│                 │ 低延迟 <1ms           │ 强一致性但慢          │
├─────────────────┼──────────────────────┼─────────────────────┤
│ 实时推送        │ WebSocket ✅          │ HTTP 轮询            │
│                 │ 服务端主动推送         │ 简单但延迟高          │
├─────────────────┼──────────────────────┼─────────────────────┤
│ 出队原子性      │ Lua Script ✅         │ 应用层乐观锁          │
│                 │ 单次网络往返          │ 多次往返 + 冲突重试    │
├─────────────────┼──────────────────────┼─────────────────────┤
│ 号源计数器      │ Redis INCR ✅         │ 数据库自增 ID         │
│                 │ 无锁高性能            │ 受限于 DB 写入        │
├─────────────────┼──────────────────────┼─────────────────────┤
│ 消息解耦        │ Redis Pub/Sub ✅      │ Kafka                │
│                 │ 轻量，延迟低          │ 持久化好但重          │
└─────────────────┴──────────────────────┴─────────────────────┘
```

### 一句话总结

> **以 Redis Sorted Set 为核心队列引擎，用 score 编码优先级+时间，Lua 保证原子出队，WebSocket 驱动大屏实时刷新，PG 兜底持久化与审计** — 在保证公平性的前提下实现毫秒级叫号响应。
